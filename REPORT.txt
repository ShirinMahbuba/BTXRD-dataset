----------------------------------------------------------------------------------------------------
  THE FIVE DEFECTS FIXED, AND THE ONE REPORTED
----------------------------------------------------------------------------------------------------
    F1  early stopping fired on a gap-penalised score that flattens while AUROC climbs.
        v8 stopped at ep 22 and v6 at ep 26 - each on its own AUROC MAXIMUM.
        v9 stops on raw val AUROC, patience 10, armed after epoch 15.
    F2  LR 1e-4 x 0.05 = 5e-6 on the backbone. v9 runs 0.0002 x 0.1 = 2e-05.
    F3  the gap was being closed by pushing train DOWN, which took val with it.
        v9 closes it by lifting val: mask supervision, multi-task heads, more signal.
    F4  CutMix and constant-fill erasing injected label noise on a localised lesion.
    F5  the EMA warmup reached d=0.81 after 40 epochs - a 5-step window, i.e. no EMA.
    F6  negative case groups over-merge: group-level positive rate 0.71
        against an image-level 0.50. MEASURED AND REPORTED, not
        silently corrected. Subdividing them by perceptual hash would split real
        multi-view cases apart and CAN leak; over-merging only costs sample size.

----------------------------------------------------------------------------------------------------
  v9.2 - THE HEAD WAS OVERFITTING, NOT (ONLY) THE BACKBONE
----------------------------------------------------------------------------------------------------
    The first v9 run hit train acc 1.0000 by epoch 2 WHILE THE BACKBONE WAS STILL
    FROZEN - proof the 4-branch dual-view head, not backbone fine-tuning, was doing
    the memorising. Fixed structurally, not just with more dropout:
      - single view by default (2 branches, not 4) - USE_ROI_VIEW = False
      - embedding/transformer dim cut 160 -> 128, heads 4 -> 4
      - dedicated 0.25 dropout on the final classifier only
      - WD 0.02 -> 0.05, dropout/droppath/aug raised
    The dual-view ROI branch is kept as an ablation row ('+ ROI view (dual scale)')
    rather than deleted, so the report can show whether it is worth its capacity cost.

----------------------------------------------------------------------------------------------------
  v9.3 - HARD AUGMENTATION (data-level fix for head memorisation)
----------------------------------------------------------------------------------------------------
    Even after the v9.2 capacity cut, the head memorised training images in a single
    epoch. Root cause: the augmentation pipeline was not diverse enough to prevent
    the ~400 K-parameter head from converging to 2685 training images in one pass.
    v9.3 fixes this at the DATA level with a fundamentally stronger augmentation:
      backbone       : effnetv2s (20.2 M) -> effnetb0 (5.3 M), same 1280-ch output
      AUG_STRENGTH   : 1.35 -> 0.6
      CLAHE          : random clip 1.5-4.0, 8x8 grid — X-ray standard preprocessing
      elastic deform : random Gaussian displacement field (40% per image per epoch)
      perspective    : random corner displacement, simulates off-axis acquisition (35%)
      crop scale     : floor 0.55 -> 0.30 (3x more spatial variety at full strength)
      solarize       : random threshold pixel inversion — breaks intensity memorisation
      motion blur    : horizontal / vertical — simulates acquisition motion
      noise          : Gaussian + Poisson (quantum noise) + salt-and-pepper
      grid shuffle   : 4x4 patch permutation (25% prob) — destroys texture layouts
      erasing        : up to 0 noise-filled patches <= 15%
      consistency    : KL(view1, view2) dual-view regularisation (weight 0.0)
      WD 0.05 -> 0.005, HEAD_DROPOUT 0.50 -> 0.25, FREEZE_EPOCHS 4 -> 2

----------------------------------------------------------------------------------------------------
  LIMITATIONS, STATED
----------------------------------------------------------------------------------------------------
    - Case groups are RECONSTRUCTED. BTXRD ships no patient identifier, so protocol A
      is a best-effort reconstruction, not ground truth. It errs toward over-merging,
      which costs data efficiency and can never create leakage.
    - Normal radiographs carry no bone-site metadata, so their group key is only
      (centre, age, sex) and over-merges unrelated patients. See F6.
    - The segmentation head is supervised only where an annotation exists; its IoU is
      a diagnostic that the auxiliary loss did something, not a segmentation result.
    - Protocol B is reported because it is the official BTXRD protocol and makes the
      numbers comparable. It is not leakage-safe and is never presented as such.
